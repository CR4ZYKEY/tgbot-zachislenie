# Telegram-бот «Зачисление в школу»

Ведёт родителя по шагам зачисления в онлайн-школу (ЦПСО / EdPalm) в течение учебного года.
Полная спецификация: `docs/spec.md` — карта экранов, кнопок и переходов. **Читай её перед любой правкой сценария.**

## Стек

- TypeScript, Node.js 22, NestJS
- grammY как провайдер Nest (не Telegraf scenes)
- PostgreSQL + Prisma
- Сценарий — YAML, схема валидируется zod при старте
- `@nestjs/schedule` — тик планировщика, только в процессе воркера

## Архитектура: два процесса

- `bot` — диалоги, long polling
- `worker` — напоминания, тик раз в минуту, выгрузка в Google Sheets

Планировщик не запускается внутри `bot`. Падение рассылки не должно ронять диалоги.

## Жёсткие правила

1. **Тексты сообщений и кнопок живут только в YAML-сценарии.** Ни одной строки текста, показываемой родителю, в `.ts` файлах. Это требование заказчика (второй продукт должен добавляться без правки кода) и критерий приёмки.
2. **Состояние — только в Postgres.** Ни сессий grammY, ни памяти процесса. `stage`, `resume_point`, `deferred_stage1` переживают рестарт.
3. **Только inline-кнопки.** Reply-клавиатуры нет нигде.
4. **Свободный ввод ровно в трёх местах:** имя (S2), телефон (S2b), отзыв о Городе (E1.5). Больше нигде — всё остальное кнопками.
5. **Персональные данные.** Собираем только: имя, телефон, Telegram ID, пакет, класс, статус, ответы по шагам, отметки чек-листов. Паспортные данные, данные документов, сведения о здоровье не сохраняем никогда — свободные поля фильтруются на входе.
6. **Никаких интеграций.** Ни платформы, ни CRM, ни платёжки. Всё, что бот знает, он получил от родителя кнопками.
7. **Прямых ссылок на разделы платформы не даём** — только текстовые пути и скриншоты.

## Тон и словарь

- К родителю на «вы».
- Слова «ребёнок» и «ученик» не употребляются нигде. Основная формулировка — **«ваш герой»**, строчными, склоняется свободно. Употребляется только там, где без называния не обойтись; в остальных случаях фраза строится через действие родителя.
- Стилистика супергеройская, в тон метафоре Города: «доступ открыт», «снаряжение получено», «путь открыт».
- Тон не тревожный. Сроки — ориентир и помощь, а не угроза. Счётчик дней не показываем, слова «просрочено» нет.
- Одно сообщение — один вопрос — 2–4 кнопки — 2–3 строки текста.

## Модель напоминаний

Два класса триггеров, не смешивать:

- **Относительные** — от действия родителя (отложенный этап 1 +3 дня, этап 2 день 3 и 7, «напомнить завтра»).
- **Абсолютные** — от `cohort_year` родителя (01.03, 01.04, 01.05, 20.05, 31.05 — аттестации; 31.03, 30.04, 20.05, 29.05 — продление).

Правила:
- прошедшие абсолютные триггеры не создаются;
- абсолютный триггер ближе 14 дней от старта не создаётся;
- даты справок: `max(относительная дата, абсолютный порог)`;
- тихие часы 10:00–21:00 МСК, не более одного касания в сутки;
- три неотвеченных касания подряд — пауза по текущему этапу.

Очередь — таблица `jobs` в БД с `dedup_key`. **При старте воркер разбирает просроченные задачи**, а не только новые: локальный запуск переживает сон машины.

## Команды

```bash
docker compose up -d postgres
npm run start:dev      # бот
npm run worker:dev     # воркер
npx prisma migrate dev
npm run scenario:check # валидация YAML по zod-схеме
```

`prisma migrate deploy`, никогда не `db push`.

## Чего не делать

- Не зашивать тексты в код, даже временно, даже «для теста».
- Не поднимать второй процесс на том же токене — Telegram начнёт делить апдейты между ними, половина нажатий «провалится».
- Не тестировать напоминания боевым токеном. Для разработки отдельный бот у @BotFather.
- Не коммитить `.env`.
- Не добавлять классы 9 и 11 и пакеты кроме Базового — вне скоупа первой версии.
